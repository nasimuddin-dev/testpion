# Cloud readiness, stage 1 (branch cloud-ctx)

Source: `planning/review-2026-10-22-scalability.md` (the P0/P1 list and its "Proposed sequence"). Rule kept throughout: the window talks to the engine only over RPC, the engine is host-agnostic and safe for several people in one process, and nothing changes for the desktop app. Architecture caps were not raised (`backend.ts` is 938 lines of 950; everything new is in modules).

## What stays for stage 2 (and why)

Measured on this commit.

1. **Async store interfaces (P0 #1, the gate for CLD-003/004/005).** `IWorkspaceStore`, `IMetaStore`, async `SecretStore.get` in `storage/interfaces.ts`; `FileWorkspaceStore` wraps today's sync class; `tsc` then lists the call sites to `await`. Measured: `be.ws.` 438 uses and `be.store` 38 in the backend; about 404 store method calls across core and the backend (`store.`/`ws.` + get/list/save/delete/read/write/rename/duplicate/move/import); `.meta.` 160; `secrets.get(` 19; `WorkspaceStore` named in 197 core files; sync `fs` calls: 1,003 in 126 core files and 157 in the backend (a Postgres/object-storage implementation only needs the ones behind the three interfaces; the rest are local-disk concerns). The handlers are already `async`; convert handlers, then runner, AI, MCP tools, the CLI last. Also `Atomics.wait` in `fsutil.ts` (async retry for the backend's writes). Reason it was not done here: ~700 mechanical edits in files the SQLite/fsutil agent is editing in parallel (metastore, fsutil), and it needs its own review.
2. **Revisions and conflict errors (P0 #4).** `expectedVersion` on `saveCollection`/`saveEnvironment`/`saveLibrary` (the window already sends it for `col.save`; extend to the others), the ops log (`col.patch`), meta into SQLite. Depends on 1.
3. **One run orchestrator, `runner/run-service.ts`.** `runTests`/`runCollection` have 22 call sites in 18 files (backend 2, CLI 5, MCP tools 4, AI 4, runner 6 ...); dataset caps differ (100k/100k/10k). Ratchet: `runTests(`/`runCollection(` only in `run-service.ts` and `monitors.ts`.
4. **Typed handlers.** The generated parameter types cover the 328 methods of the table, and 25 answers are typed; 195 handlers still have no table entry (`tests/fixtures/rpc-params-without-entry.txt`) and `Handler = (params: any)`. Next: move the result types next to the handlers (`satisfies Handlers<Contract>`), shrink the fixture to empty, type `call` for every method, snapshot the contract JSON.
5. **Registry ratchets.** 12 `case 'grpc'|'websocket'|'mqtt'|'kafka'|'socketio'` outside `protocols/` in core; kind branches outside `kinds/` (`kind === '…'` lines also count unrelated kinds, so ratchet per file against today's number when this is picked up); renderer `kind-ui` registry.
6. **Cloud host.** A session router (`Backend` per session, events addressed by session id, WebSocket with a per-client queue: `SseHub`'s policy is the starting point), authentication filling `CallMeta.user`, `can(capability)` enforced per method group, and the permission table. The dev bridge stays single-session.
7. **Smaller leftovers from the review's P1/P2 lists:** per-store `FileCache` (text/parsed caches are a shared 64 MB pool), `onOwnWrite(root, fn)` so a write notifies one listener, `WorkspaceManager` out of `workspace.ts`, `COUNT`/retention of runs, `col.list` paging, chunked upload for imports, `registerPolicy` per organisation (the global policy is fine for one operator), chatty-stream caps (unverified), external-secrets cache LRU.

## Decision on script workers for the desktop app

**Off by default in the desktop app; on with `TESTPION_SCRIPT_WORKERS=1` (or a size, `0` for none) or `BackendHost.scriptWorkers`.** The e2e suite and the performance budgets pass with the pool on (below), the pool costs nothing at start (workers are made at the first script), and a server host turns it on. What is not proven is the packaged app: the worker is `dist-electron/script-worker.cjs` (685 KB, built by `build-main.mjs`, found next to `main.cjs`) and in the installed build that path is inside `app.asar`, where `worker_threads` may not load a file (the SQL worker uses an eval string for this reason). So the default flips only after the install check: install the build, start it with `TESTPION_SCRIPT_WORKERS=1`, run `core`, `visualizer-sandbox`, `settings-script-trust`, `mcp-trust`, `wf-run-ci` with `--exe`; if a worker cannot start, `AppServices.scriptWorkersProblem` says why and scripts run in the main thread as before. If it does not load from the archive, add `dist-electron/script-worker.cjs` and `dist-electron/lazy/**` to `asarUnpack` in `electron-builder.yml`.
