## 1. Starting a capture: two start buttons, three ways to decrypt

What is there (verified): when the proxy is off, the header shows **Start capturing** (default variant,
`views/DebuggerView.tsx:558-560`) and **Capture all traffic** (primary, `:562-573`); the subtitle (`:548`) explains the
difference. **Capture all traffic** (`captureAll`, `:348-352`) = start the proxy → set the system proxy (toast) → `readHttps`
(`:328-347`): if the root is not trusted, the **See inside HTTPS?** dialog, **Install and decrypt** / **Only tunnels**;
on Install the certificate goes into the user store (`packages/core/src/debugger/certificate.ts:185-198`, Windows
`certutil -user -addstore`, macOS `security add-trusted-cert`, Linux Chrome's NSS db) and decryption turns on. The
**Capture** menu (`:469-502`) still has **Everything on this computer (the system proxy, restored on stop)** → the same
`captureAll`. The **HTTPS** menu's **Decrypt HTTPS** (`:615-621`) and the banner's **Decrypt HTTPS** (`:719-725`) call
`debug.decrypt { on: true }` directly, which only makes sure a root exists (`backend/handlers/debugger.ts:586-593`), never
checks or installs trust.

## 10. First HTTPS API call: click count

Scenario: a first-time user wants to see **one HTTPS call their own program makes** (e.g. `GET https://api.example.com/v1/me`).

**A. From a browser (the Fiddler / Charles case), Windows, fresh machine**

| Step | Place | Clicks |
|---|---|---|
| Open the Debugger | Rail ▸ More… ▸ Debugger (it is hidden under More… by default) | 2 |
| **Capture all traffic** | Debugger header | 1 |
| **See inside HTTPS?** → **Install and decrypt** | dialog | 1 |
| Windows' own "install this root certificate?" | OS dialog | 1 |
| Toast: "close and reopen your browser"; reopen it, load the page | the browser | 2+ |
| Find the call among every program's traffic | the grid: **Hide tunnels** is off, so one CONNECT row per host sits between the requests; then All applications ▸ chrome.exe | 2 |
| **Total** | | **9** (Fiddler: 1 on first run after its own certificate wizard, then 0; Charles: 0 after the one-time certificate install; Proxyman: 0 + a per-app "enable SSL proxying" click) |

What costs: More… (the view is off the rail: a product choice), the reopen (unavoidable once), the tunnel rows (the
default should hide tunnels while decryption is on, or stay off and list only decrypted rows), the program filter.
Declining once (**Only tunnels**) turns this into 13+ clicks (§1 row 3).

**B. From a Node / Python / curl program (the API-client case)**

| Step | Place | Clicks |
|---|---|---|
| Open the Debugger | Rail ▸ More… ▸ Debugger | 2 |
| **Capture ▸ A terminal** (Capture all does not catch these programs; the proxy starts by itself) | header menu | 2 |
| **HTTPS ▸ Decrypt HTTPS** | header menu (this path never installs trust) | 2 |
| Run the program in the opened terminal | terminal | — |
| It fails: the program does not trust the root; the Error tab says to install the root and restart, or the row is a failed tunnel | the grid | 1 |
| **HTTPS ▸ Root certificate… ▸ Install** (Windows store: Node, Python and curl **do not read it**) | dialog | 3 |
| Learn `NODE_EXTRA_CA_CERTS` / `REQUESTS_CA_BUNDLE` / `--cacert` from the docs or the certificate dialog's list, set it, run again | terminal | — |
| **Total** | | **10 + a docs visit**; the opened terminal sets `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY` (`capture.ts:149`) but not the CA variables, although the root's path is known |

Fix for B (P1, `packages/core/src/debugger/capture.ts:147-183`, `DebuggerView.tsx:490-493`): when decryption is on, the
terminal opened by **Capture ▸ A terminal** also exports `NODE_EXTRA_CA_CERTS`, `REQUESTS_CA_BUNDLE`, `SSL_CERT_FILE`
and `CURL_CA_BUNDLE` pointing at `testpion-root.pem`, and the **Copy the lines for …** items include them; then B is
Debugger → Capture ▸ A terminal → HTTPS ▸ Decrypt (which should also offer the one-click trust: §1 row 3) → run: 6
clicks, no docs visit. Guard: unit on `proxyShellLines(url, { rootPath })` and `openTerminalWithProxy` env.

**macOS / Linux, same scenarios**: A adds the keychain password prompt (macOS) or, on Linux, trust lands in Chrome's
NSS db only (`certificate.ts:197`) and `rootCertificateTrusted` returns `undefined` (`:230`), so **See inside HTTPS?**
asks on every click; a site on `localhost` needs the `localhost.` trick the app never mentions (§1 row 6).
