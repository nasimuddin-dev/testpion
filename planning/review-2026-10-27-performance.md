# Performance review — 2026-10-27

Read-only review of the engine (`packages/core`), the desktop backend (`apps/desktop/backend`), the CLI (`packages/cli`), the MCP server and the renderer (`apps/desktop/src`) at commit `208dd40c`, against the quality bar "clean and super fast in all cases" (33 ms two-frame floor for the UI). Baselines: `planning/review-2026-10-22-performance.md` and `planning/ui-audit-2026-10-21-performance.md`; every finding of theirs was checked in the current tree (§5). All 25 perf gate files were run serially today (`--no-file-parallelism`, dist built 19:13-19:37, other agents running): **25 files / 173 tests passed**, every budget inside (§3). Micro-benchmarks for the reasoned costs below were run in plain Node on this machine (scratchpad scripts, not in the repo): a 14 MB JSON body → `JSON.parse` 73 ms, deep `redact` walk 165 ms, `JSON.stringify(…, null, 2)` 60 ms; a 433 KB collection parse 2.6 ms; `RegExp.test` 0.28 µs, glob → `new RegExp` → test 2.5 µs, `vm.Script.runInContext({timeout})` 138 µs.

Severity: **P0** breaches a budget, or blocks the Electron main thread / the UI for more than 33 ms in a realistic case · **P1** measurable waste · **P2** hygiene. Nothing is fixed here; "Guard" names the test that would pin the fix. Reminder that frames everything: the backend, the proxy and all `debug.*` handlers still run in Electron's **main process** (`apps/desktop/electron/main.ts:416`), so a synchronous block there stalls the window's IPC, the proxy's sockets and every RPC.

## 0. Summary

- **No gate is breached.** The old breaches are gone: `git-perf` 285 ms (was 1,057), `load-stats` 5 M samples + 10 snapshots in 167 ms, trace batch longest block 3 ms (was ~750), `main.cjs` 7.75 MB under its 8 MB budget, `tools/list` 204,603 B under 200 KiB, CLI `collections --json` 170 ms (was 320-500), MCP spawn → `initialize` 222 ms (was 580).
- **Three budgets have almost no headroom**: `main.cjs` 265 KB (3.2 %) under 8 MB while ~575 KB of `electron-updater` + `qrcode` are bundled eagerly although `await import()`ed; `tools/list` **1,955 chars** under its 200 KiB gate (two more tools breach it); `perf-debugger` sort-and-scroll already at the 34 ms floor while a non-seq sort re-sorts 5,000 rows per sync.
- **New P0s** are all "a big body on the main thread": the GraphQL send path (desktop and runner) was skipped when R-3/S-4 fixed HTTP — the whole parsed response (preview cap **64 MB**, `graphql.ts:72`) is deep-redacted and pretty-printed to keep 64 KB / 16,000 chars; `http.send` re-parses the whole request body to collect secrets (73 ms at 14 MB); the Debugger's `TimelinePanel` (F-19's third part) is still unmemoised, uncapped and keyed on `rows`, so a Shift-range with the Timeline dock open reconciles thousands of elements per sync; saving/stopping a full debugger session is one synchronous HAR build.
- The script worker pool exists and is tested but is **off** on the desktop host (`scriptWorkersWanted` → 0): every script pass is synchronous QuickJS on the main thread, up to the 2,000 ms script timeout.
