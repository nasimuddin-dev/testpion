# UI performance audit — 2026-10-21

Read-only audit of the desktop renderer (`apps/desktop/src`), its backend (`apps/desktop/backend`) and the storage hot paths in `packages/core` against the quality bar "clean and super fast in all cases". Everything below was verified by reading the current tree (file:line) unless marked **unverified**; the measurements are from the existing perf plans run today on the development build (one plan at a time).

Summary: `perf-large-workspace` passes with every interaction at the two-frame floor (34 ms); `perf-debugger` passes 5 of 6 steps (the sixth could not run: the proxy port 8899 is held by the owner's running TestPion); `perf-output-download` **fails its 50 ms worst-frame gate on both attempts (66 ms, 50 ms)** — marginal on a busy machine, to be rerun alone. The code audit found two P0 jank sources that the plans do not yet exercise (Debugger detail panes re-pretty-printing up to 512 KB on every capture sync; the Console remounting all 500 rows per event with index keys), and a set of P1 refetch storms (GitView, `stats.attention`, Monitors) and render-time work (JsonTree collapse, WebSocket filter, MCP merge) with concrete fixes and the test that would pin each.

Method (memory `ui-perf-profiling`): `npm run e2e -w @testpion/desktop -- --only perf-*`, two-frame floor ≈ 33 ms; `npm run build -w @testpion/desktop` for chunk sizes. The `_perf-*` plans (`_perf-history-traces`, `_perf-debugger-5000`, `_perf-explorer-9000`, `_perf-flow-canvas-500`, `_perf-tests-1000`, `_perf-debugger-flood`) are profiling aids outside the suite and need a `TESTPION_PROFILE=1` build; they were not run (no budgets to compare against).
